# 買方配案

依條件（行政區/社區/路名 + 總價 + 房數等）掃 i智慧Pro 流通物件，逐筆取出物件規格、
承辦專員姓名/電話/店別，並點「分享」拿到 i智慧 公開分享網頁連結（免登入、客戶可直接開），
整理成一段文字，複製貼上就能傳給客戶。

啟動模式：**CDP attach**（跟桌面「自動比對專約」工具同一套手法）——開一個獨立 profile 的
Chrome（帶 `--remote-debugging-port=9223`），第一次手動登入 i智慧一次，之後腳本用
`connect_over_cdp` 連進去操作、不存帳密、不用處理登入流程。

## 日常用法（推薦：GUI，雙擊就能用）

雙擊 **啟動工具.vbs**（不會開黑窗，pythonw 背景執行）：

1. 按「啟動 Chrome」→ 第一次要在跳出的 Chrome 視窗手動登入 i智慧（is.ycut.com.tw），
   之後登入態會記住，不用再登
2. 填行政區/總價/房數等條件（只有行政區關鍵字必填）
3. 想先確認條件抓得對不對，先勾「只看筆數」跑一次（快，不開詳情頁）
4. 沒問題再取消勾、按「開始查詢」，跑完結果會顯示在畫面上、**自動複製到剪貼簿**，
   直接 Ctrl+V 貼給客戶

## 第一次設定（一次性，GUI/CLI 共用）

```powershell
cd scripts/buyer-match
py -m pip install -r requirements.txt
```

不需要 `playwright install chromium`——CDP attach 用的是你電腦上真的 Chrome，
不是 Playwright 自帶的瀏覽器。`output/`（每次查詢存檔）會在跑的時候自動產生，
不要外流／已 gitignore。

**登入態（Chrome profile）放在 `%LOCALAPPDATA%\buyer-match-chrome`，不在工具資料夾裡。**
2026-07-30 搬過去的，原因：桌面那份工具在 OneDrive 底下，OneDrive 會同步整個 Chrome
profile（實測 5943 個檔、4.75 GB），連 `Default\Network\Cookies` 都被變成雲端佔位檔
（ReparsePoint）。Chrome 關著時 OneDrive 把它變成「線上檔案」，下次開就等於被登出——
同一個坑在 KEIS 的 CSV 上踩過一次。要換位置設環境變數 `BUYER_MATCH_PROFILE_DIR`
（`chrome_cdp.py` 的 `profile_dir()` 跟 `open_real_chrome.bat` 都吃這個）。

⚠️ **不要用工作管理員硬殺那個 Chrome**（也不要 `Stop-Process`）：cookie 是關閉時才寫回
磁碟的，硬殺等於自己製造登出。要關就正常按 X，或送 CDP `Browser.close`。

### 選填：讓過期自動重新登入（不用手動打帳密）

獨立 Chrome profile 沒有你平常 Chrome 記住的密碼，第一次登入之後 cookie 一般能撐一陣子，
但過期時預設要手動切到 Chrome 視窗重新輸入。想要過期也自動處理：

```powershell
cp .env.example .env
# 編輯 .env，填 ISMART_ACCOUNT / ISMART_PASSWORD
```

填了之後，腳本偵測到被導去登入頁會自動嘗試登入。**沒填也完全能用**，只是過期當下要自己手動登入一次。

⚠️ 這段自動登入用的是「找帳號/密碼欄位＋找登入按鈕」的通用選取器，因為目前還沒機會在不登出你
現有 session 的情況下先看過 i智慧登入頁長什麼樣。**第一次真的觸發、如果自動登入沒成功**，
腳本會印出清楚的訊息、退回原本「請手動登入」的流程，不會卡死——把那時登入頁的樣子（或截圖）
告訴我，我就能把選取器鎖精確，之後就不會再失敗。

## 進階：命令列模式

如果不想開 GUI，先雙擊 `open_real_chrome.bat` 開好 Chrome、登入 i智慧，再直接跑 .py：

```powershell
# 苓雅區、300~500萬，最多處理 15 筆（預設）
python buyer_match.py --district 苓雅區 --price-min 300 --price-max 500

# 多行政區（最多 3 個，逗號分隔）+ 房數 + 車位（有車位、限平面或昇降平面）
python buyer_match.py --district 苓雅區,三民區 --price-max 600 --rooms-min 2 --parking 有 --parking-type 坡道/平面,昇降/平面

# 社區/路名關鍵字（--area）可以單獨用，也可以跟 --district 併用做進一步縮小
python buyer_match.py --area 三多商圈 --price-max 800 --rooms-min 2 --limit 10
python buyer_match.py --district 苓雅區 --area 三多 --price-max 800

# 只想先看有幾筆符合、不逐筆開詳情頁抓專員/分享連結（快很多，適合先確認條件抓得對不對）
python buyer_match.py --district 苓雅區 --price-max 500 --list-only

# 除錯：開詳情頁但不點分享（不會跳確認視窗、不產生分享連結）
python buyer_match.py --district 苓雅區 --price-max 500 --dry-run --limit 3
```

| 參數 | 預設 | 說明 |
|---|---|---|
| `--district` | 不限 | 行政區，逗號分隔最多 3 個，例 `苓雅區,三民區`。走網站真的行政區下拉選單（不是文字比對），2026-07-28 截圖實測過 |
| `--area` | 不限 | 社區/路名關鍵字（丟進「編號、案名、社區、部份地址」搜尋欄），可跟 `--district` 併用；`--district`／`--area` 至少填一個，兩個都空會掃全高雄市 |
| `--price-min` / `--price-max` | 不限 | 總價區間（萬）——Python 端過濾（讀清單卡片文字），不是網站的總價下拉 |
| `--rooms-min` | 不限 | 至少幾房（讀「格局」欄位，如「2房」）——同上，Python 端過濾 |
| `--usage` | 不限 | 用途關鍵字，例 `住宅`（可排除店面/透天等） |
| `--parking` | 不限 | `無` 或 `有`。網站真的「進階搜尋→車位」篩選（不給就不動，維持網站預設「不限」，比較快） |
| `--parking-type` | 不限 | `--parking 有` 才有作用，逗號分隔多選：坡道/平面、坡道/機械、昇降/平面、昇降/機械、庭院、平移/機械、獨立車庫、塔式車位 |
| `--limit` | 15 | 最多處理幾筆詳情頁（每筆要開新分頁+點分享，筆數越多越久） |
| `--list-only` | off | 只列篩選後清單，不開詳情頁 |
| `--dry-run` | off | 開詳情頁抓專員資訊但不點分享 |

i智慧 預設就是總價由低到高排序，`--limit` 會拿排序後前 N 筆命中的（等於先給便宜的）。

⚠️ **`--price-min`/`--price-max`/`--rooms-min` 不是網站篩選，是 Python 讀清單資料後自己過濾**——
好處是不用碰更多 Angular 元件、夠準也夠穩；代價是掃描量沒有先被總價/房數縮小。單一行政區
（如苓雅區）整區筆數可能上千筆，`--list-only` 掃卡片有 15 頁（450 筆）的安全上限，超過會印
`翻頁達上限` 警告——這種情況建議加 `--district` 縮小（比純文字 `--area` 搜整區準且快，因為
是網站真的伺服器端行政區過濾，不是掃完全部再比對文字）。

## 跑完會怎樣

- 每筆物件整理成一段：標題／地址／用途格局屋齡坪數／總價＋編號／專員姓名電話／店別／
  i智慧公開分享連結。
- 全部結果印在畫面上、存成 `output/<時間戳>_<area>.txt`（已 gitignore）、
  **同時複製到剪貼簿**，直接 Ctrl+V 貼給客戶。

## 常見狀況

**「連不到 http://localhost:9223」**
`open_real_chrome.bat` 沒開，或背景還有沒關乾淨的 chrome.exe 把這次啟動併走了。
工作管理員砍掉全部 chrome.exe 再重跑 `open_real_chrome.bat`。

**「i智慧登入態過期」**
腳本會直接報錯提示。切到 `open_real_chrome.bat` 開的那個 Chrome 視窗重新登入 i智慧，
不用重開腳本、重跑一次指令即可。

**分享連結抓不到某幾筆**
`open_detail_and_fetch` 抓不到「分享」按鈕或跳出來的分頁逾時，會印 WARN 但不中斷整批，
那幾筆就只有規格+專員資訊、沒有連結。

## 房地/i智慧配案（房地客需 → i智慧即時案源）

2026-07-29 加：房地（agent.foundi.info）有多邊形圈選功能但案源新舊不一，i智慧沒有圈選但
即時；於是改成「客戶需求存在房地（含畫多邊形），工具負責讀出範圍再回頭去 i智慧現查」，
不用再一個一個社區手動搜、一個一個分享連結複製貼上。

**第一次設定**：跟 i智慧一樣，同一個 CDP Chrome（`open_real_chrome.bat` 開的那個）
也要手動登入一次房地（agent.foundi.info）。`open_real_chrome.bat` 已經改成會同時開
兩個分頁，兩邊都登過一次、之後都不用再登。

**⚠️ 房地只能手機掃 QR Code 登入**（沒有帳號密碼可以放 `.env`），所以自動重登這條路
天生不存在，只能「偵測到沒登入 → 推 LINE 喊人」。好消息是房地的 `sessionid` 是
**持久 cookie、有效期約 29 天**（2026-07-30 實測），關掉瀏覽器也不會掉，所以很少需要重掃。

**i智慧 為什麼老是要重登？**（2026-07-30 查清楚）它的登入 cookie
（`.AspNetCore.Identity.Application`、`idsrv.session`、`oidc*`）**全部是 session cookie，
Chrome 一關就沒了**，而 `token` 的壽命只有 12 分鐘、靠持續使用才會自動續。所以使用者
自己的瀏覽器（整天開著又一直在用）永遠不用重登，而工具這個開開關關的 Chrome 每次都要。
這不是工具少了記憶功能，是永慶 SSO 的設計——已經用 `.env` 帳密自動重登解掉了。

**日常用法（推薦：GUI，雙擊就能用）**：雙擊 **房地i智慧配案.vbs**（視窗標題是
「房地/i智慧配案」；檔名不能有斜線，Windows 檔名不允許 `/`。跟單獨查 i智慧的
「啟動工具.vbs」是不同工具，不要點錯）。

**2026-07-30 起是三層下拉，不用打字**：開工具時（Chrome 已開就自動）從房地把
「群組 → 客戶 → 客需」整棵樹讀回來，直接點選。房地那邊新增客戶／改名字之後，
按「從房地重新讀客戶清單」就會更新，不用改 code。

| 選法 | 行為 |
|---|---|
| 群組＝**（★ 全部群組：一組一組依序跑完）** | A買→B買→C買… 全部跑完（2026-08-04 加）。客戶／客需下拉會變灰，因為每一組的每個人都會跑。粗估每組 45 分鐘 × 組數，確認視窗會直接把時數算給你看 |
| 客戶＝**（整組跑：全部客戶）** | 跑這個群組底下全部客戶的全部客需，每個客需各自存檔、跑完印總表（會花幾十分鐘，按下去會先跳確認）|
| 客戶＝某人、客需＝**（這位客戶的全部客需）** | 只跑他所有條件（通常幾分鐘）|
| 客戶＝某人、客需＝某個條件 | 單查一條，最快 |

讀不到清單時（例：房地登入態過期）狀態列會講原因，三個下拉會自動解鎖成可以手打，
不會卡死。

結果會顯示在畫面上並自動複製到剪貼簿。想先確認條件抓得對不對，可以勾「只抓專員資訊，
不點分享連結」先跑一次。

⚠️ **不要直接雙擊 `run_customer_match.py` 這支 .py 檔**——它需要客戶名字當參數，
雙擊等於沒帶參數直接跑，會因為缺參數馬上報錯、視窗一閃就關掉（2026-07-29 實測踩過），
要嘛用上面的 GUI，要嘛照下面「命令列模式」帶參數執行。

**進階：命令列模式**

```powershell
python run_customer_match.py 采儒                    # 用她底下第一個子條件
python run_customer_match.py 采儒 --need 文化中心周圍   # 指定子條件
python run_customer_match.py 采儒 --need 文化中心周圍 --newest      # 優先看新案（🆕 標記）
python run_customer_match.py 采儒 --need 文化中心周圍 --limit-areas 3 --dry-run  # 先試跑幾個關鍵字看看
```

流程：讀房地那個客需的候選清單 → 抽社區/路名關鍵字（社區名優先，沒有才退用路名）
+ 讀存好的篩選條件 → 逐關鍵字丟 `buyer_match.py` 的 `match_areas()` 去 i智慧
現查 → 用「社區/路名＋樓層＋坪數＋總價」這組指紋去重（同一戶被永慶多店簽委託時只留
一筆代表，其他店的聯絡方式附註在同一筆，不會給客戶重複連結）→ 輸出格式跟單獨跑
`buyer_match.py` 一樣（印出/存檔/複製剪貼簿）。

### 房地的條件怎麼對應到 i智慧（2026-07-29 補齊）

原則是「房地怎麼設定條件，i智慧就要怎麼找」。房地摘要（`div.filter-preview` 那行字）
會被解析成下列條件帶去 i智慧：

| 房地條件 | i智慧怎麼處理 |
|---|---|
| **框選（多邊形）** | i智慧沒有等價的圈選功能 → **從候選清單的地址反推涵蓋哪些行政區**（出現最多的前 3 個），帶去 i智慧 的「縣市區域」下拉。再加上社區/路名關鍵字本來就是從那塊多邊形裡抽出來的，兩層合起來逼近原本的地理範圍 |
| 地址模式列出的行政區 | 直接帶去「縣市區域」下拉 |
| 有車位 | 走 i智慧「進階搜尋→車位=有」真篩選 |
| 總價 / 單價 / 房數 / 衛浴數 / 屋齡 / 主建物坪數 / 土地坪數 / 樓層 / 不要頂樓 / 型態用途 | Python 端讀卡片文字後過濾（`passes_filters()`）|

⚠️ **「主建物坪數」要比對 i智慧 的「主建」欄位，不是「建物」**：i智慧 卡片有三個獨立坪數
（`建物`＝含公設總坪、`主建`＝主建物、`地坪`＝土地）。2026-07-29 一度誤比對成 `建物`，
總坪一定大於主建，等於條件被放寬、會放進不符合的物件。現在 `Card` 三個欄位都有抓，
輸出也會一起印（`建物53.695坪（主建42.737坪）｜地坪5.039坪`）方便你一眼核對。

⚠️ **抓不到的欄位一律不擋**：樓層解析不出來（土地案、`B1` 這種寫法）、卡片沒有主建坪數
等情況，一律當作「不知道」讓它通過，不當成不符合——跟這個 repo 其他工具（KEIS 系列）
一致的原則，寧可漏篩也不要誤刪掉客戶可能要看的物件。

### 新案（NEW 標記）

i智慧 會在案名後面標一個 NEW。**它不是文字、也不是 `<img>`，是自訂元素
`<case-new-tag-svg>`（內嵌 SVG）**——2026-07-29 找了很久才確認：搜文字「NEW」、
掃 `assets/*new*` 圖檔都找不到（唯一含 new 的 `news.svg` 其實是「商耕報」按鈕圖示）。
現在 `Card.is_new` 就是認這個 tag name，輸出會在案名前面加 🆕。

⚠️ **要看到新案一定要先切排序**：i智慧 預設排序是「總價：低>高」，第一頁全是便宜的舊案、
一個 NEW 都沒有（實測 newCount=0）。加 `--newest` 會把排序切成「上架：新>舊」，
實測 30/30 張卡都正確標到 🆕。GUI 版這個選項**預設是開的**。

⚠️ 切排序的 JS 有個坑：選項是 inline 展開（不是 cdk overlay），**點選項時只能點選項本身**，
往上連父層一起點會把選單收起來、排序不生效（`sort_by_newest()` 註解裡有記）。

⚠️ **行政區超過 3 個會整個不篩**：i智慧「縣市區域」下拉最多勾 3 個，房地那邊可以設更多
（實例：「公買 透天賴秀真」設了 6 個區）。硬截斷成前 3 個會靜靜漏掉一半範圍，所以改成
**印 WARN + 完全不篩行政區**，退回只靠社區/路名關鍵字限制範圍（關鍵字本來就是從房地
候選清單抽的，範圍不會超出去，只是少一層保險）。

⚠️ **型態/用途是「OR」比對**：房地摘要寫「大樓,透天、店面」會解析成 `['店面','透天','大樓']`，
物件的用途欄位命中**任一個**就算通過，不是全部都要符合。

⚠️ **刻意不做品牌篩選**：使用者只要 i智慧 裡永慶自己的案源，而 i智慧 本來就只有永慶
體系的在架物件，所以房地摘要裡的「信義,永慶」那段直接忽略不解析。房地候選清單裡的
非永慶案子，到 i智慧 搜不到是正常的（會顯示 0 筆），不是比對失敗。

⚠️ **還沒對應過去的**：車位型態（平面式/機械式）。房地摘要有寫，但 i智慧 那邊要多開
一層「進階搜尋→車位型態」多選下拉，目前只做到「有/無車位」。

⚠️ **2026-08-01 訂正**：舊版這裡寫「路名關鍵字常搜不到（實測 `福建街` 0 筆）」，
是錯的——`福建街` 現場實測搜得到 14 筆，使用者截圖當場抓到。優先用社區名的真正原因
是**路名太籠統**（同一條路一次跑出十幾筆不相干的物件），社區名比較精準，不是路名搜
不到東西。某個社區在 i智慧 搜 0 筆是正常的（房地混了非永慶品牌的案子，i智慧 本來就
只有永慶自己的在架案源）。

**大樓保險機制**（`foundi_need.fallback_hints` + `buyer_match._spec_matches`，
2026-08-01）：社區名搜 0 筆時，自動改搜路名重試，但因為路名籠統，額外要求**這一戶
自己的樓層／主建坪數**（抓自候選卡片本身，不是客需的範圍條件）要對得上（坪數容許
±1 坪）才收，避免把同條路上不相干的物件也算進去。已用真實資料端到端驗證：假社區名
逼出保險路徑 → 搜 `福建街` 回 11 張候選 → 用樓層 10＋主建 31.39 坪篩出剛好 1 筆正確
的。透天沒有社區名可用，本來就是直接搜路名（見上面「大樓保險機制」表格），沒有這層
保險——這是之後可以擴充的方向，但目前透天候選只有一個路名關鍵字，沒有「路名搜到但
不確定是不是那一戶」的機制可比對。

⚠️ 房地那邊的候選清單抓的是「當下畫面」，不是 API——`foundi_need.py` 的 DOM 選擇器
（`.panel-heading-container.hover-property-summary` 等）是實測房地頁面挖出來的，房地
改版的話這段可能要跟著調，症狀會是 `[INFO] 讀到 0 筆候選`。

## 進階：批次跑整個群組（`run_group_match.py`）

> 💡 **平常不用直接跑這支**——GUI 把「客戶」欄位留空就是走這條路。這段是給要用
> 命令列、或想加參數微調的時候看的。

2026-07-29 加：`run_customer_match.py` 一次只跑一個客戶的一個子條件，這支負責把
房地「客需條件」某個群組（A買/B買/C買/其他）底下**所有客戶、每個客戶存的每一個
子條件**全部跑完，各自存檔。

```powershell
python run_group_match.py A買                          # 整組全部跑
python run_group_match.py A買 B買 C買                    # 三組依序跑完（GUI「★ 全部群組」走這條）
python run_group_match.py A買 --newest                  # 整組跑、優先看新案（🆕 標記）
python run_group_match.py A買 --customer 采儒            # 只跑這組裡的某個客戶（她全部子條件）
python run_group_match.py A買 --dry-run --limit 5        # 先小規模試跑，抓時間感、不點分享連結
python run_group_match.py A買 --only-new                 # 只給上次沒出現過的＋改價的（排程用的模式）
```

跑完印一張總表（每個「客戶／子條件」命中幾筆或哪裡失敗），複製到剪貼簿；每個
「客戶／子條件」各自存一個檔在 `output/`，不會混在一起。單一子條件失敗（例如房地那邊
文字比對不到）只會跳過那一筆繼續跑，不會讓整組半途而廢。

給多個群組時（`A買 B買 C買`）CDP 只連一次，一組跑完接著下一組；某一組整組失敗
（例如群組名字在房地找不到）也只是印警告跳過，後面幾組照跑——整批要好幾小時，
不該因為第一組出事就整晚白等。最後印的是跨組總表（每組一段）。

⚠️ **一整組可能要跑很久**：候選清單/關鍵字數量差很多——2026-07-29 實測 A買裡
「巨蛋凹子底」這個子條件就讀到 170 筆候選、去重後 72 個關鍵字要逐一查 i智慧，
而「京典」「采揚天」這種純關鍵字搜尋的子條件通常只有 1 個關鍵字。整組真的跑起來
可能是幾十分鐘起跳，**第一次一定要先 `--dry-run --limit 5` 試跑**估時間，不要一次
全開。

## 每天 08:10 自動跑（`daily_run.py` + Windows 工作排程）

2026-07-29 加：每天早上自動跑 **A買** 整組，跑完把「哪位客戶幾筆」的總表推到 LINE。

**安裝（門市電腦跑一次就好）**

```powershell
cd scripts\buyer-match
powershell -ExecutionPolicy Bypass -File .\install-daily-task.ps1
```

**先確認兩件事**（順序照做，各 10 秒）

```powershell
python daily_run.py --notify-test   # 手機收得到 LINE 就代表通知那段通了
python daily_run.py --dry-run       # 完整跑一次但不點分享連結
```

**它會自己做的事**

1. CDP Chrome（port 9223）沒開就自己開起來，等到連得上為止（最多 90 秒）
2. **先驗登入態**：房地、i智慧各檢查一次。任何一邊沒登入就**推 LINE 叫人去登、當場中止**
   ——絕不會靜靜撈到 0 筆然後回報「今天沒新案」
3. 跑 A買 整組（正式模式，有分享連結），每個「客戶／子條件」各自存檔在 `output/`
4. **只輸出「上次沒出現過的」＋「總價變了的」**（見下面「上次看過的不要再出現」）
5. 推 LINE 總表；失敗、沒登入、跑到一半炸掉也都會推。log 在 `daily_run.log`

### 「上次看過的不要再出現」（2026-07-30 加）

每天 80 幾筆有一大半是昨天看過的同一批，所以排程那班只給新的：

- **怎麼認同一戶**：`社區或地址 ｜ 樓層 ｜ 坪數`（`Card.unit_key()`），**刻意不含總價**。
  ⚠️ 不用 i智慧案號當主鍵——同一戶被永慶多店簽委託會有好幾個案號，用案號的話
  「同一戶換一家店重掛」會被誤判成新案。案號只在欄位缺到組不出指紋時當備援。
- **總價變了要重報**：同一戶價格不同就當「🔻 降價 60 萬（1580 → 1520 萬）」重新給一次，
  降價是可以打電話的理由，不能被當重複吃掉。
- **⚠️ 同一戶多店委託、各店開價不一樣**（2026-07-30 使用者提出，第一版真的會誤報）：
  `dedup_by_fingerprint` 只合併「連開價都一樣」的重複委託，所以同一戶店A掛 1580、
  店B掛 1520 時兩筆都會活著。一戶只記一個價的話，第二筆會被當成「降價 60 萬」，
  而且隔天兩筆順序一換就變「調漲 60 萬」，天天來回跳。所以：
  ① 先照 unit_key 把同一戶的多筆委託併成**一組**（完全不看開價）
  ② 比較基準用**這一戶的最低開價**（買方在意的就是最低那個，而且與撈到的順序無關）
  ③ 記憶同時存 `prices`（各店開價），新增一家店掛更高價不會觸發任何回報
  ④ **只有最低開價變低才報降價**；變高（多半是便宜那筆委託下架了）只更新記憶、
     不吵你，數字列在總表的「漲價 N 戶略過」
  ⑤ 輸出用最低開價那筆當代表，後面附一行「（同一戶另有 2 筆委託，開價 1580／1600 萬）」，
     免得客戶問「別家怎麼比較便宜」答不出來
- 計數單位是**「戶」不是「筆」**：一戶被 3 家店委託，對你來說是一戶要不要看，不是三筆。
- **記憶按「客戶／客需」分開**：同一戶對不同客戶都是新資訊，全域去重會害別的客戶漏看。
- **保留 30 天**沒再出現就刪（案子下架了）。刻意不用「這次沒出現就刪」——房地/i智慧掛掉
  那天會撈到 0 筆，那種邏輯會把記憶整個清光、隔天全部重報。
- 狀態檔：`state/seen.json`（不進 git）。想從零開始就直接刪掉它。
- 手動想看**完整清單**：`python daily_run.py --all`，或直接用 GUI（GUI 一律全寫）。

**⚠️ 房地沒有自動重登**（i智慧 有 `.env` 帳密可以自動登入，房地沒有）。房地登入態
大概每隔一陣子就會過期，過期那天早上手機會收到「🔑 房地要重新登入」，這時候要到
門市電腦那個配案專用的 Chrome 視窗手動登一次，然後雙擊桌面「房地i智慧配案」補跑。
