1. **Railway `EXECUTIONS_DATA_SAVE_ON_SUCCESS` 一律保持 `all`**
   改 `none` 會讓所有含 Wait 節點的流程無聲死掉（煞車 10 分鐘就是 Wait）。
   空間不夠的正確解法是調降 `MAX_AGE`，不是關掉紀錄。
   清執行紀錄一律用 **TRUNCATE**，絕不用 API 批次 DELETE（08-09 停機經過見 `incidents.md`）。
2. **AI 回傳壞掉時寧可不發，絕不硬發**
   保底邏輯只要「讓流程繼續」而不管「送出去的東西對不對」，就是在把故障洗成看起來成功的樣子。
   對外送出的東西一律要有形狀檢查。
3. **KEIS `show_in_web=false` 的案子絕對不發**（屋主/門市沒同意網路露出）。擋在 `篩選候選` 最上游。
