# 591-ad — 591 售屋廣告刊登全流程

## 何時使用

使用者給一個 houseol 案件編號（委託書編號，格式如 `AA1072565`）並要刊登 591 售屋廣告。

## 前置檢查（約 30 秒，跑完才開始，不要做到一半才發現卡住）

1. 591 後台已登入：開 `https://user.591.com.tw/post/first?type=sale&redirect_from=old` 沒被導去登入頁。中途被登出整輪要重來。
2. houseol 已登入：資料來源那兩個網址打得開。
3. KEIS API 通得過（照片與最後同步都要用），憑證在 `C:\Users\user\OneDrive\桌面\keis\.env`。

## 前置：需要使用者提供

1. **案件編號**（例：`AA1072565`）
2. **房屋型態**（別墅／透天厝／公寓／華廈／電梯大樓）——來源頁的「型式/用途」只會寫「大樓」這種籠統分類，無法自動判斷是公寓/華廈/電梯大樓，一律要問使用者，不要自己猜。
3. 如果是第一次幫**不同店/不同專員**的案件跑這個流程：追蹤本 skill 下面「資料來源」段落的 `UID`/`UAID`/`AID` 是否要換，先問使用者，不要照抄舊值。

## 資料來源

### 物件事實（不動產售屋資料）
```
https://hq.houseol.com.tw/auto.asp?m=SellHouse&f=print19&torf=false&listbox={案件編號}%23001&LoginPrint=1
```
用瀏覽器打開，`get_page_text` 抓表格內容。這份資料表尾寫「本表單係店內部流通資料，不得作為正式銷售文件」——所以只能拿來當「鐵律事實」餵給 Codex/填表單，**不能整段照抄當文案**。

### 照片（走 KEIS API，不要開瀏覽器點按鈕）

```bash
python .claude/skills/591-ad/keis.py photos AA1072565 --out <scratchpad>/pics
```

一行解決：反查 KEIS 物件ID → `download-images` zip → 解壓 → 印出檔案清單與總大小。
這跟臉書發文線（`yc-v3-scan-publish`）抓照片是同一條路，不用點「圖片打包下載」、不用等靜默下載、
不用翻桌面找檔名、不用問使用者。解完直接用 `mcp__claude-in-chrome__file_upload` 整批上傳到 591「房屋照片」。
（腳本會在超過 10MB 時提醒要分批上傳，也會在張數跟 KEIS 記錄對不上時警告。）

**fallback（只有 KEIS 查無此案件編號時才用）**：houseol 型錄頁

```
https://es.houseol.com.tw/Ecatalog.aspx?UID=03039&UAID=H888&No={案件編號}&AID=H888
```

`UID=03039`／`UAID=H888`／`AID=H888` 是薛力瑜、博愛凱璿店驗證過的固定值，換人/換店要先確認。
頁面上方「圖片打包下載」按鈕用 `find` 定位（座標點擊不準），點下去靜默下載到桌面，
檔名 `H888_YYYYMMDDHHMMSS.zip`，自己抓最新那個、確認時間是「剛剛」：

```powershell
Get-ChildItem "$env:USERPROFILE\OneDrive\桌面\H888_*.zip" | Sort-Object LastWriteTime -Descending | Select-Object -First 1
```

## 主流程

### Step 1. 選擇廣告類型（第1頁）

`https://user.591.com.tw/post/first?type=sale&redirect_from=old`

四層選單：刊登類型（出售，除非使用者說出租）→ 房屋法定用途（住家用）→ 房屋現況（住宅）→ 房屋型態（問使用者，見上）。選完自動跳第2頁。

### Step 2. 對數字——這步最容易錯，務必照公式算，不要憑感覺

原始頁面欄位：`總 建 坪`／`主建物`／`附屬建物`／`公共設施`／`公設車位`／`地坪`。

**不要手算，跑這支腳本**（手算是這整套流程最容易靜靜出錯的地方，錯了會印在公開廣告上）：

```bash
python .claude/skills/591-ad/ping.py --main 主建物 --annex 附屬建物 --public 公共設施 --park 公設車位 --total 總建坪 --parkdesc "來源頁停車方式原文"
```

沒有公設車位就不要帶 `--park`；**透天/店面一定要帶 `--land 地坪`**（591 有獨立的「土地坪數」欄位，大樓案沒有這欄）。腳本直接吐出 591 要填的「共有部分／車位面積／車位類型／權狀坪數（含或不含車位）」，算不出來會 `exit 1` 並叫你停下來問使用者——照做，不要自己湊。

⚠️ **透天案的「主建物」在來源頁是分樓層列的**（1樓 12.384／2樓 12.384／3樓 12.384），
要自己加總成 37.152 再餵給 `--main`，不要只抓第一層。

腳本背後的規則（人工覆核時看這段）：

- **坪數一律無條件捨去（truncate，不是四捨五入）到小數點後 2 位**，例：`12.918` → `12.91`。
- **只在最後輸出時捨去一次，中間相加全部用原始精度**（推測來源頁的「總建坪」就是 `trunc(主+附+公設)`）。
  （舊版寫「兩種算法取對得上的那種」是錯的：AA1072565 兩種都得 30.67，那個例子根本分不出來，等於沒驗證過。2026-09-19 改成單一算法。）
  ⚠ 誠實說：AA1072565 只證明了「總建坪是捨去不是四捨五入」（四捨五入會得 30.68），沒證明是「先加後捨」還是「先捨後加」。
  所以這條是假設，不是事實——但 `ping.py` 會拿算出來的結果去對總建坪，假設不成立就 exit 1 停手，不會靜靜算錯。真的 exit 1 就回頭問使用者。
- 回推檢查（`主+附+共有部分+車位 = 總建坪`）在「車位子集」分支下只是飄移檢查，不是獨立驗算（扣掉再加回來會抵消），別當成雙重保險。
- **權狀坪數一律用來源頁的「總建坪」捨去到 2 位**，兩種車位分支都一樣，不用自己加總。（來源有時給 3 位小數，例：`37.153` → 填 `37.15`。）
- **地坪**（土地坪數）也是捨去 2 位，透天/店面必填。
- **分支只影響「共有部分」要不要扣車位**：
  - `trunc(主+附+公設) ≈ 總建坪` → 車位是公設的子集 → 共有部分 = `trunc(公設 − 公設車位)`，權狀選「含車位面積」
  - `trunc(主+附+公設+車位) ≈ 總建坪` → 車位外加 → 共有部分 = `trunc(公設)`，權狀選「含車位面積」
  - 沒有公設車位 → 共有部分 = `trunc(公設)`，車位面積留空，權狀選「不含車位面積」
    （⚠ 這條分支還沒有真實案件驗證過，尤其 591 那個下拉選項的實際字串，第一次遇到要人工確認）
  - 都套不上 → 停手問使用者

（AA1072565 實例：15.7 / 2.06 / 12.918 / 車位 2.966 / 總建坪 30.67 → 共有部分 9.95、車位面積 2.96、權狀 30.67 含車位）

**車位面積旁邊的「車位類型」下拉**：來源「停車方式」欄位文字對照：
- 含「機械」→ 選「機械式停車位」
- 含「平面」且不含「機械」→ 選「平面式停車位」
- 兩者都有 → 選「平面式+機械式」
- 其他/看不懂 → 選「其他」，跟使用者確認

**裝潢程度固定選「簡易裝潢」**——不管來源「現況」寫空屋還是有人住。空屋只代表沒人住，不代表沒裝潢，這是使用者的固定偏好，不要因為看到「空屋」就選「尚未裝潢」。

### Step 3. 填第2頁「填寫資料」

6 個分頁，錨點在右側：基礎資料／房屋價格／生活機能／特色描述／照片&影片／聯絡資料。

- **地址**：填到門牌號那格之後，**一律勾選「隱藏門號」**（在門牌號輸入框右邊）。
- 社區名稱：填完地址後 591 通常會自動帶出，帶錯或沒帶才用來源「大樓名稱」手動補，不要自己加「大廈」之類的字。
- 建築完工時間：來源「建築完成日」是 `105/08/26` 這種民國格式，直接拆年/月/日填。
- 售價／管理費／自備款：照來源填，自備款%系統通常自動算，不用管。
- 帶租約：填「否」，除非來源特別註明有租約。
- 生活機能：捷運站填來源「捷運站」欄位（例：`R14巨蛋`、`C1籬仔內`）。輕軌站也填這格。
- **出售樓層**：下拉只有「出售單層／出售多層」兩個選項（沒有「整棟」）。透天全棟 1-3 樓＝選「出售多層」，前後兩格填 `1` 和 `3`。
- **朝向**：選項是全稱「坐東南朝西北」，不是「東南」。
- **委託書（必填，在最下面聯絡資料區）**：查 KEIS `contract_type` 決定——`一般委託` → 選「有簽訂」；`專任委託` → 選「有簽訂專任約」。這格沒填會擋住「保存資料，下一步」，而且是法律聲明，不要亂猜：
  ```bash
  python .claude/skills/591-ad/keis.py  # 或直接打 API：property-management/?search=<案件編號> 看 contract_type
  ```
- 服務費保持預設「收取服務費」，經紀人資料那個確認框預設已勾。

⚠️ **不要一格一格點擊打字**（2026-09-19 實測：慢到使用者中斷兩次）。

**做法：用 `fill591.js`，一次呼叫填完整頁。**

1. 打開 `.claude/skills/591-ad/fill591.js`，把最上面的 `DATA` 換成這件案子的值（沒有的欄位填 `null`）
2. 整份貼進 `mcp__claude-in-chrome__javascript_tool` 執行
3. 看回傳的 JSON：**`對不上` 是空陣列才算成功**；`下拉` 五項都要是實際選到的值，不是錯誤訊息
4. 有任何一項不對就看下面的眉角對照，不要硬按下一步

2026-09-19 在乾淨表單上實測：5 個下拉、19 個文字欄位、9 個單選、文案，全部一次到位，33 秒。
（照片上傳不在腳本裡，要另外用 `file_upload`。）

下面是腳本背後的眉角，**改腳本前先看**，每一條都是踩過才知道的：

**① 純文字欄位**：native setter + 派 `input`/`change` 事件，React 才收得到
```js
function setVal(el,v){Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(el,v);
 el.dispatchEvent(new Event('input',{bubbles:true}));el.dispatchEvent(new Event('change',{bubbles:true}));}
```

**② radio / checkbox**：`input.click()` 沒用，要點外層 `label.ant-radio-wrapper`／`.ant-checkbox-wrapper`。用文字定位，不要記索引（重繪會飄）：
```js
const m=[...document.querySelectorAll('label.ant-radio-wrapper,label.ant-checkbox-wrapper')]
        .find(l=>l.innerText.replace(/\s+/g,'')==='簡易裝潢'); m.click();
```

**③ 驗狀態要看 class，不要看 `input.checked`**——591 把**所有** radio 的 `name` 都設成 `radioGroup`，
DOM 層變成同一組互斥，`checked` 會互相洗掉，但 React 自己的狀態是對的。看外層有沒有 `ant-radio-checked`：
```js
[...document.querySelectorAll('label.ant-radio-wrapper')].map(l=>l.innerText.trim()+'='+
  (l.querySelector('.ant-radio-checked')?'V':'-'))
```
（這條害我一度以為「有簽訂」跟「收取服務費」會互相取消，其實兩個都好好的。）

**④ 縣市／鄉鎮／朝向／出售型態是 antd 虛擬清單**：打字過濾**完全無效**（它只比對 value 的數字 id），
必須捲動 `.rc-virtual-list-holder` 直到選項被渲染出來再點。而且要用 `aria-controls` 找到「這個 select 自己的」
dropdown，抓 `document` 上最後一個會抓到別人的（踩過，選朝向時選到別的清單）。

**⑤ 街道是另一種元件**（不是 antd select）：一個「請輸入街道名稱」搜尋框＋街名格子，
要往搜尋框灌字再點格子。而且**縣市/鄉鎮沒先選好，街道清單會是「無此資料」**。

**⑥ 富文本（特色描述）是 ProseMirror**：`innerText=` 沒用，要 focus 後用
`document.execCommand('insertText'/'insertParagraph')` 一行一行打。

**⑦ 照片上傳後 file input 的 ref 會失效**，第二批要重新 `find` 一次。

**⑧ 每次重繪後索引會變**，灌完一批一定要回讀驗證（樓層、總樓層這兩格被重繪清空過兩次）。

**⑨ 不要碰頁面最上面的「一鍵複製物件」開關**，誤觸會把畫面跳回頂端。

### Step 4. 產文案（特色描述分頁）

**廣告標題**（6～30字）：直接用來源「案名」精簡過的版本，不誇飾。

**現況特色描述**：**由 Claude 直接寫，不要叫 Codex**（2026-09-19 使用者指示：Codex 只留給他自己手動檢查程式碼時用，不要被這個流程吃掉額度）。格式套用公司既有粉專文案的規則（跟 `scripts/codex-copy/` 同一套，只是輸出目標是 591 不是 FB）。

下面這份原本是餵給 Codex 的 prompt，現在是給 Claude 自己的寫作規格，一字不改地遵守：
```
你是台灣資深房仲文案寫手。照公司既有的粉專文案格式規則寫這則 591「現況特色描述」，規則如下（鐵律，禁止違反）：

【格式】只能有三塊：
①第一行【】標題（地段+房型+賣點關鍵字，不含價格，因為591已有獨立標題欄位）
②規格區，每行一個 emoji：📍地址 🏠格局 📐坪數 🏢樓層 💰開價，沒有值的直接省略整行
③空行後，✨亮點 2-5 條，每條「・」開頭——**這幾條必須是下面「訴求重點原文」的改寫，不准新增訴求重點以外的賣點**（不可自己加學區、屋齡、建材、電梯等其他鐵律事實類資訊到亮點區，那些都已經在規格區列過了，亮點區只能講訴求重點原文有講的地緣優勢）

【數字寫法】規格區跟亮點區的數字都要跟下面提供的原始事實一致，不能換算、不能新增沒提供的數字。

【鐵律事實】（只能用在規格區，不能杜撰其他規格）
地址：{區域}，{大樓名稱}（門牌已隱藏不可寫完整門牌號）
格局：{格局}
坪數：{權狀坪數說明}
樓層：{樓別}／{總樓高}
開價：{售價}萬

【訴求重點原文】（只能用在✨亮點區，這是唯一能寫進亮點的素材，不能新增）
{來源頁「訴求重點」欄位原文}

只輸出一個 JSON：{"現況特色描述":"...(用 \n 換行)"}，不要 markdown、不要多餘說明。
```

**規矩**：
- 亮點區的素材**只能來自來源頁的「訴求重點」欄位**，不能把坪數/格局/屋齡等其他鐵律事實塞進亮點區（那些已經在規格區列過了）——2026-09-08 這條規則是使用者在流水帳版、再條列版都不滿意之後才定案的，不要退回舊版本。
- 若來源「訴求重點」是空的，亮點區留空或跟使用者說明沒有素材可用，不要自己編。

填完用 `ctrl+a` + `Delete` 清空整個富文本框再貼新版，不要用 append 造成新舊文案疊在一起。

### Step 5. 照片＆影片、聯絡資料分頁

- 上傳全部照片到「房屋照片」，格局圖/影片非必填可略過。
- 聯絡資料通常已帶入預設名片，不用改，除非使用者另外交代。

### Step 6. 「保存資料，下一步」→ 進第3步「確認刊登方案」

**這步是花錢風險最高的地方，務必照做：**

1. 檢查加購項目是不是預設打勾（2026-09-19 看到的是「購買置頂推廣」預設勾 → 應付 547 元；另有「購買AI助手」預設沒勾），**全部取消勾選**。
2. **先取消「同意自動續費」子選項，再取消推廣本體**，順序反了子選項會殘留。取消完回讀一次確認三個 checkbox 全 false。
3. 取消完，看右下角「應付金額」**必須顯示 0 元**才能按送出。⚠️ **按鈕現在叫「立即支付」，不叫「確認刊登方案」**（591 改字了，0 元時按它就是送出刊登，不會扣錢）。任何非 0 元，都要停下來跟使用者確認要不要付費，不能自己決定付。
4. 應付金額確認是 0 元就**直接按下去送出，不用回頭問使用者**（2026-09-19 使用者指示：只要不用另外花錢就不需要他確認）。
5. 送出後如果跳「你還可以買OOO」的加購彈窗（挽留話術、損失曝光數字），一律點右上角 X 或「確定」放棄，不要點「立即支付」。

### Step 7. 同步 KEIS 廣告追蹤（刊登成功後一定要做）

拿到 591 廣告網址後：

```bash
python .claude/skills/591-ad/keis.py sync AA1072565 --url591 https://sale.591.com.tw/home/house/detail/2/{編號}.html
```

先看 dry-run 印出來的「會怎麼改」對不對，對了再加 `--apply` 真的寫進去。腳本會：

1. 從 Notion 廣告 DB 用案件編號撈「永慶官網連結」（KEIS 廣告追蹤只收永慶/台慶連結，houseol 網址會 500）
2. 用那個連結找既有廣告 → **有就併進去**（填 `adcase_url591`、`adcase_platforms` 補上 `591`，臉書連結原封不動）；沒有就新建一筆
3. 寫完回讀一次驗證，臉書連結有沒有被洗掉也一併檢查

**Notion 查無此案件編號**（代表這案沒被 v3 發文線收過，例如屋齡/總價未達發文門檻）→ 腳本會停下來叫你補 `--yc-url`。
反查方法（2026-09-19 實測一次就中）：

```
https://buy.yungching.com.tw/search?kw={案件編號的數字部分}
```

例：`AG1727762` → `?kw=1727762` → 唯一結果 `buy.yungching.com.tw/house/6914085`。
**開頁面驗 JSON-LD 的 `productID`**：應該是相同數字、只有字母前綴不同（`AG1727762` → `YC1727762`），
再確認行政區與案名對得上才用。對不上就不要硬建，會留下沒登錄的孤兒廣告（跟 v3 發文線同一條紅線）。

**舊廣告已關閉的情況**：同一物件如果以前登過 591，KEIS 會留一筆 `is_expired=True` 的舊紀錄。
KEIS 慣例是一物件一筆，所以要**重開舊那筆**而不是新開：加 `--reopen`（把 is_expired 改回 False）
和 `--price 總價`（舊紀錄記的是舊開價）。腳本 dry-run 會把這兩項一起列出來。

給使用者這則廣告連結（`https://sale.591.com.tw/home/house/detail/2/{591物件編號}.html`，物件編號從 URL 或「查看該筆廣告」連結拿），提醒 591 通常要等 3 分鐘才會在搜尋列表顯示，請使用者自己人工檢查一次。

**要下架/改掉這則廣告**（測試刊出來的、或發現填錯）：591 後台「我的廣告」→ 找到該筆 → 「編輯」改內容，或「關閉」下架。重刊不要重新開一筆新廣告，會變成重複刊登。

## 規矩（絕對不要違反）

- ❌ 確認刊登方案那步，應付金額不是 0 元絕對不能自己按下去，一定要停下來問
- ❌ 坪數不要手算，一律跑 `ping.py`；腳本 exit 1 就是叫你停下來問，不要改參數硬湊
- ❌ 不要把來源頁「本表單係店內部流通資料，不得作為正式銷售文件」那段免責文字之外的內容整段照抄當文案，鐵律事實只能拿來組裝，不能整段貼
- ❌ 文案亮點區不能自己加訴求重點以外的賣點，即使那些是真事實（坪數/格局/學區等）——那些已經在規格區列過
- ❌ 坪數不能四捨五入，一律無條件捨去到小數點後2位
- ❌ 裝潢程度不要看到「空屋」就自動選「尚未裝潢」，固定選「簡易裝潢」
- ❌ 車位/公設子集算不出來就停下來問，不要瞎猜哪個是子集哪個是外加
- ❌ 591 刊登成功後不要忘記 Step 7 的 KEIS 同步；沒登錄的廣告會被開罰
- ❌ 同步 KEIS 不要為了 591 另開一筆廣告——KEIS 慣例是一物件一筆、多平台掛同一筆（實測 266 筆裡零重複）
- ❌ 不要改成只 PUT 單一欄位。PUT 是不是 partial update 沒驗過，一律 GET 整筆→改→PUT 整筆→回讀驗，否則可能把臉書連結洗掉
