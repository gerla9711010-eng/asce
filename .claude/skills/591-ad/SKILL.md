# 591-ad — 591 售屋廣告刊登全流程

## 何時使用

使用者給一個 houseol 案件編號（委託書編號，格式如 `AA1072565`）並要刊登 591 售屋廣告。

## 前置檢查（約 30 秒，跑完才開始，不要做到一半才發現卡住）

1. 591 後台已登入：開 `https://user.591.com.tw/post/first?type=sale&redirect_from=old` 沒被導去登入頁。中途被登出整輪要重來。
2. houseol 已登入：資料來源那兩個網址打得開。
3. KEIS API 通得過（照片與最後同步都要用），憑證在 `C:\Users\user\OneDrive\桌面\keis\.env`。

## 前置：需要使用者提供

1. **案件編號**（例：`AA1072565`）
2. **房屋型態**（別墅／透天厝／公寓／華廈／電梯大樓）——**只有來源「型式/用途」寫「大樓」時才問**（分不出公寓/華廈/電梯大樓，不要自己猜）。
   寫透天/別墅/公寓/華廈的由 `prep.py` 直接對應，不用停下來問（2026-10-14 使用者同意）。
3. 如果是第一次幫**不同店/不同專員**的案件跑這個流程：追蹤本 skill 下面「資料來源」段落的 `UID`/`UAID`/`AID` 是否要換，先問使用者，不要照抄舊值。

## 資料來源

### 物件事實（不動產售屋資料）


### 照片（走 KEIS API，不要開瀏覽器點按鈕）

```bash

```

一行解決：反查 KEIS 物件ID → `download-images` zip → 解壓 → 印出檔案清單與總大小。

### Step 1. 選擇廣告類型（第1頁）

**用 `prep.py` 給的網址直接開第 2 頁，不用點第 1 頁。** 網址參數：`kind=9`（出售住宅）、`purpose=3`（住家用）、
`shape`＝房屋型態（公寓 1／電梯大樓 2／透天厝 3／別墅 4／華廈 5，2026-10-14 逐一點過）、`region`＝縣市（高雄 17；
其他縣市沒驗過，不帶 region 時 591 會跳縣市選單讓人點）。

手動備援：`https://user.591.com.tw/post/first?type=sale&redirect_from=old`，
四層選單：刊登類型（出售，除非使用者說出租）→ 房屋法定用途（住家用）→ 房屋現況（住宅）→ 房屋型態（問使用者，見上）。選完自動跳第2頁。

### Step 2. 對數字——這步最容易錯，務必照公式算，不要憑感覺

原始頁面欄位：`總 建 坪`／`主建物`／`附屬建物`／`公共設施`／`公設車位`／`地坪`。
（`prep.py` 已經自動做這步；下面是規則本體，以及沒用 `prep.py` 時的手動做法。）

**不要手算，跑這支腳本**（手算是這整套流程最容易靜靜出錯的地方，錯了會印在公開廣告上）：

```bash
python .claude/skills/591-ad/ping.py --main 主建物 --annex 附屬建物 --public 公共設施 --park 公設車位 --total 總建坪 --parkdesc "來源頁停車方式原文"
```

沒有公設車位就不要帶 `--park`；**透天/店面一定要帶 `--land 地坪`**（591 有獨立的「土地坪數」欄位，大樓案沒有這欄）。腳本直接吐出 591 要填的「共有部分／車位面積／車位類型／權狀坪數（含或不含車位）」，算不出來會 `exit 1` 並叫你停下來問使用者——照做，不要自己湊。

⚠️ **透天案的「主建物」在來源頁是分樓層列的**（1樓 12.384／2樓 12.384／3樓 12.384），
要自己加總成 37.152 再餵給 `--main`，不要只抓第一層。

腳本背後的規則（人工覆核時看這段）：

- **坪數一律無條件捨去（truncate，不是四捨五入）到小數點後 2 位**，例：`12.918` → `12.91`。
- **只在最後輸出時捨去一次，中間相加全部用原始精度**（推測來源頁的「總建坪」就是 `trunc(主+附+公設)`）。
  （舊版寫「兩種算法取對得上的那種」是錯的：AA1072565 兩種都得 30.67，那個例子根本分不出來，等於沒驗證過。2026-09-19 改成單一算法。）
  ⚠ 誠實說：AA1072565 只證明了「總建坪是捨去不是四捨五入」（四捨五入會得 30.68），沒證明是「先加後捨」還是「先捨後加」。
  所以這條是假設，不是事實——但 `ping.py` 會拿算出來的結果去對總建坪，假設不成立就 exit 1 停手，不會靜靜算錯。真的 exit 1 就回頭問使用者。
- 回推檢查（`主+附+共有部分+車位 = 總建坪`）在「車位子集」分支下只是飄移檢查，不是獨立驗算（扣掉再加回來會抵消），別當成雙重保險。
- **權狀坪數一律用來源頁的「總建坪」捨去到 2 位**，兩種車位分支都一樣，不用自己加總。（來源有時給 3 位小數，例：`37.153` → 填 `37.15`。）
- **地坪**（土地坪數）也是捨去 2 位，透天/店面必填。
- **分支只影響「共有部分」要不要扣車位**：
  - `trunc(主+附+公設) ≈ 總建坪` → 車位是公設的子集 → 共有部分 = `trunc(公設 − 公設車位)`，權狀選「含車位面積」
  - `trunc(主+附+公設+車位) ≈ 總建坪` → 車位外加 → 共有部分 = `trunc(公設)`，權狀選「含車位面積」
  - 沒有公設車位 → 共有部分 = `trunc(公設)`，車位面積留空，權狀選「不含車位面積」
    （2026-10-14 AG1727776 透天實證：主建物各層＋騎樓＋地下層加總 = 總建坪，591 選項字串就是「不含車位面積」）
  - 都套不上 → 停手問使用者

（AA1072565 實例：15.7 / 2.06 / 12.918 / 車位 2.966 / 總建坪 30.67 → 共有部分 9.95、車位面積 2.96、權狀 30.67 含車位）

**車位面積旁邊的「車位類型」下拉**：來源「停車方式」欄位文字對照：
- 含「機械」→ 選「機械式停車位」
- 含「平面」且不含「機械」→ 選「平面式停車位」
- 兩者都有 → 選「平面式+機械式」
- 其他/看不懂 → 選「其他」，跟使用者確認

**裝潢程度固定選「簡易裝潢」**——不管來源「現況」寫空屋還是有人住。空屋只代表沒人住，不代表沒裝潢，這是使用者的固定偏好，不要因為看到「空屋」就選「尚未裝潢」。

### Step 3. 填第2頁「填寫資料」

6 個分頁，錨點在右側：基礎資料／房屋價格／生活機能／特色描述／照片&影片／聯絡資料。

- 售價／管理費／自備款：照來源填，自備款%系統通常自動算，不用管。
- 帶租約：填「否」，除非來源特別註明有租約。來源現況寫「出租」或案名寫「收租」時先問使用者（AG1918099 現況出租→使用者說否）。
- **有車位但來源沒給車位坪數**（車位欄寫「公設車位」、卻沒有「公設車位 X 坪」那行，車位坪數併在公設裡）：`prep.py` 會警告並設
  `parkingInPrice: true`。問使用者；AA1072556 使用者選「不填坪數、售價選含車位價格、文案註明含平面車位」，
  591 前台會自己顯示「車位：平面式，已含售金內」。
- 主建物寫成區間（「1-2 樓 35.238 坪」）、地址沒樓層的大樓低樓層店住，`prep.py` 會判成出售多層 1–2。
- 生活機能：捷運站填來源「捷運站」欄位（例：`R14巨蛋`、`C1籬仔內`）。輕軌站也填這格。
- **生活機能勾選／特色標籤**（買方篩選會用到，2026-10-14 起）：`prep.py` 依**訴求重點原文的明確字眼**產 `amenities`／`tags`，
  寧可漏勾不要錯勾——學區欄不算（每間都有學區）、市場欄只寫泛稱「傳統市場」不算、特色標籤要原文出現「明星學區／制震／重劃區」。

下面是腳本背後的眉角，**改腳本前先看**，每一條都是踩過才知道的：

**① 純文字欄位**：native setter + 派 `input`/`change` 事件，React 才收得到
```js

 el.dispatchEvent(new Event('input',{bubbles:true}));el.dispatchEvent(new Event('change',{bubbles:true}));}
```

**② radio / checkbox**：`input.click()` 沒用，要點外層 `label.ant-radio-wrapper`／`.ant-checkbox-wrapper`。用文字定位，不要記索引（重繪會飄）：
```js
const m=[...document.querySelectorAll('label.ant-radio-wrapper,label.ant-checkbox-wrapper')]
        .find(l=>l.innerText.replace(/\s+/g,'')==='簡易裝潢'); m.click();
```

**③ 驗狀態要看 class，不要看 `input.checked`**——591 把**所有** radio 的 `name` 都設成 `radioGroup`，
DOM 層變成同一組互斥，`checked` 會互相洗掉，但 React 自己的狀態是對的。看外層有沒有 `ant-radio-checked`：
```js
[...document.querySelectorAll('label.ant-radio-wrapper')].map(l=>l.innerText.trim()+'='+
  (l.querySelector('.ant-radio-checked')?'V':'-'))
```
（這條害我一度以為「有簽訂」跟「收取服務費」會互相取消，其實兩個都好好的。）

**④ 縣市／鄉鎮／朝向／出售型態是 antd 虛擬清單**：打字過濾**完全無效**（它只比對 value 的數字 id），
必須捲動 `.rc-virtual-list-holder` 直到選項被渲染出來再點。而且要用 `aria-controls` 找到「這個 select 自己的」
dropdown，抓 `document` 上最後一個會抓到別人的（踩過，選朝向時選到別的清單）。

**⑤ 街道是另一種元件**（不是 antd select）：一個「請輸入街道名稱」搜尋框＋街名格子，
要往搜尋框灌字再點格子。而且**縣市/鄉鎮沒先選好，街道清單會是「無此資料」**；鄉鎮剛選完清單要一兩秒才回來，
腳本會等面板出現「第1/N頁」才開始搜。

**⑥ 富文本（特色描述）是 ProseMirror**：`innerText=` 沒用，要 focus 後用
`document.execCommand('insertText'/'insertParagraph')` 一行一行打。

**⑦ 照片上傳後 file input 的 ref 會失效**，第二批要重新 `find` 一次。

**⑧ 不要用 input 的全域索引找格子**：勾「含車位面積」會多插車位面積那列、勾管理費「有」會多一格，
後面整排位移（2026-10-14 踩過：管理費數字灌進月繳下拉、捷運站灌進公車站下拉、標題灌進火車站）。

- ❌ 確認刊登方案那步，應付金額不是 0 元絕對不能自己按下去，一定要停下來問

- ❌ 不要把來源頁「本表單係店內部流通資料，不得作為正式銷售文件」那段免責文字之外的內容整段照抄當文案，鐵律事實只能拿來組裝，不能整段貼
