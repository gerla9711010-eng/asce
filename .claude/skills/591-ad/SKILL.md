# 591-ad — 591 售屋廣告刊登全流程

## 何時使用

使用者給一個 houseol 案件編號（委託書編號，格式如 `AA1072565`）並要刊登 591 售屋廣告。

## 前置：需要使用者提供

1. **案件編號**（例：`AA1072565`）
2. **房屋型態**（別墅／透天厝／公寓／華廈／電梯大樓）——來源頁的「型式/用途」只會寫「大樓」這種籠統分類，無法自動判斷是公寓/華廈/電梯大樓，一律要問使用者，不要自己猜。
3. 如果是第一次幫**不同店/不同專員**的案件跑這個流程：追蹤本 skill 下面「資料來源」段落的 `UID`/`UAID`/`AID` 是否要換，先問使用者，不要照抄舊值。

## 資料來源

### 物件事實（不動產售屋資料）
```
https://hq.houseol.com.tw/auto.asp?m=SellHouse&f=print19&torf=false&listbox={案件編號}%23001&LoginPrint=1
```
用瀏覽器打開，`get_page_text` 抓表格內容。這份資料表尾寫「本表單係店內部流通資料，不得作為正式銷售文件」——所以只能拿來當「鐵律事實」餵給 Codex/填表單，**不能整段照抄當文案**。

### 照片
```
https://es.houseol.com.tw/Ecatalog.aspx?UID=03039&UAID=H888&No={案件編號}&AID=H888
```
`UID=03039`／`UAID=H888`／`AID=H888` 是這次 session（薛力瑜、博愛凱璿店）驗證過的固定值，換人/換店要先確認。頁面上方找「圖片打包下載」按鈕（用 `find` 定位，座標點擊不準），點下去是靜默下載，跟使用者要下載到的檔名（`H888_YYYYMMDDHHMMSS.zip`），在 `C:\Users\user\OneDrive\桌面\` 找。解壓縮到 scratchpad，用 `mcp__claude-in-chrome__file_upload` 一次全部上傳到 591「房屋照片」（15 張左右 < 1MB 沒問題，若太多張導致單次超過 10MB 要分批上傳）。

## 主流程

### Step 1. 選擇廣告類型（第1頁）

`https://user.591.com.tw/post/first?type=sale&redirect_from=old`

四層選單：刊登類型（出售，除非使用者說出租）→ 房屋法定用途（住家用）→ 房屋現況（住宅）→ 房屋型態（問使用者，見上）。選完自動跳第2頁。

### Step 2. 對數字——這步最容易錯，務必照公式算，不要憑感覺

原始頁面欄位：`總 建 坪`／`主建物`／`附屬建物`／`公共設施`／`公設車位`／`地坪`。

**坪數一律無條件捨去（truncate，不是四捨五入）到小數點後 2 位**，例：`12.918` → `12.91`，不是 `12.92`。

**判斷公設車位是不是公共設施的子集**（這是關鍵）：
```
算 A = 主建物 + 附屬建物 + 公共設施（三個都先捨去2位再加，或加完再捨去，兩種算法差在最後一位，取「總建坪」數字對得上的那種）
如果 A ≈ 網頁上的「總建坪」（差在捨去誤差內）：
    → 公設車位是公共設施的子集（已經算在裡面了）
    → 591「共有部分」= 公共設施 − 公設車位（捨去2位）
    → 591「車位面積」= 公設車位（捨去2位）
    → 591「權狀坪數」選「含車位面積」，數字＝總建坪
否則（A 明顯小於總建坪，差距接近公設車位的坪數）：
    → 公設車位是外加的，不含在公共設施裡
    → 591「共有部分」= 公共設施（捨去2位，不用扣車位）
    → 591「車位面積」= 公設車位（捨去2位）
    → 591「權狀坪數」＝主建物+附屬建物+公共設施+公設車位，選「含車位面積」
兩種算法都套不出總建坪 → 停下來，把數字列出來問使用者，不要自己猜
```
（2026-09-08 的 AA1072565 案例是第一種：15.7+2.06+12.918=30.678≈30.67=總建坪，所以車位2.966捨去2.96、共有部分12.918-2.966=9.952捨去9.95）

**車位面積旁邊的「車位類型」下拉**：來源「停車方式」欄位文字對照：
- 含「機械」→ 選「機械式停車位」
- 含「平面」且不含「機械」→ 選「平面式停車位」
- 兩者都有 → 選「平面式+機械式」
- 其他/看不懂 → 選「其他」，跟使用者確認

**裝潢程度固定選「簡易裝潢」**——不管來源「現況」寫空屋還是有人住。空屋只代表沒人住，不代表沒裝潢，這是使用者的固定偏好，不要因為看到「空屋」就選「尚未裝潢」。

### Step 3. 填第2頁「填寫資料」

6 個分頁，錨點在右側：基礎資料／房屋價格／生活機能／特色描述／照片&影片／聯絡資料。

- **地址**：填到門牌號那格之後，**一律勾選「隱藏門號」**（在門牌號輸入框右邊）。
- 社區名稱：填完地址後 591 通常會自動帶出，帶錯或沒帶才用來源「大樓名稱」手動補，不要自己加「大廈」之類的字。
- 建築完工時間：來源「建築完成日」是 `105/08/26` 這種民國格式，直接拆年/月/日填。
- 售價／管理費／自備款：照來源填，自備款%系統通常自動算，不用管。
- 帶租約：填「否」，除非來源特別註明有租約。
- 生活機能：捷運站填來源「捷運站」欄位（例：`R14巨蛋`）。

⚠️ 填表單時**先點對輸入框再打字**，591 是 SPA，捲動後座標會位移，之前踩過兩次坑：一次打到別的欄位串接了舊文字、一次誤觸「一鍵複製物件」開關把畫面跳回頂端。每次打字前用 `find` 精準定位元素、或打完立刻截圖確認內容對不對，錯了要整格清空（`ctrl+a` + `Delete` 或 `triple_click`）重填，不要在後面接著打造成串接。

### Step 4. 產文案（特色描述分頁）

**廣告標題**（6～30字）：直接用來源「案名」精簡過的版本，不誇飾。

**現況特色描述**：呼叫 Codex CLI 產生，格式固定套用公司既有粉專文案的格式（跟 `scripts/codex-copy/` 系統同一套規則，只是輸出目標是591不是FB）：

```
codex exec --skip-git-repo-check
```
prompt 範本（把 {} 換成實際值）：
```
你是台灣資深房仲文案寫手。照公司既有的粉專文案格式規則寫這則 591「現況特色描述」，規則如下（鐵律，禁止違反）：

【格式】只能有三塊：
①第一行【】標題（地段+房型+賣點關鍵字，不含價格，因為591已有獨立標題欄位）
②規格區，每行一個 emoji：📍地址 🏠格局 📐坪數 🏢樓層 💰開價，沒有值的直接省略整行
③空行後，✨亮點 2-5 條，每條「・」開頭——**這幾條必須是下面「訴求重點原文」的改寫，不准新增訴求重點以外的賣點**（不可自己加學區、屋齡、建材、電梯等其他鐵律事實類資訊到亮點區，那些都已經在規格區列過了，亮點區只能講訴求重點原文有講的地緣優勢）

【數字寫法】規格區跟亮點區的數字都要跟下面提供的原始事實一致，不能換算、不能新增沒提供的數字。

【鐵律事實】（只能用在規格區，不能杜撰其他規格）
地址：{區域}，{大樓名稱}（門牌已隱藏不可寫完整門牌號）
格局：{格局}
坪數：{權狀坪數說明}
樓層：{樓別}／{總樓高}
開價：{售價}萬

【訴求重點原文】（只能用在✨亮點區，這是唯一能寫進亮點的素材，不能新增）
{來源頁「訴求重點」欄位原文}

只輸出一個 JSON：{"現況特色描述":"...(用 \n 換行)"}，不要 markdown、不要多餘說明。
```

**規矩**：
- 亮點區的素材**只能來自來源頁的「訴求重點」欄位**，不能把坪數/格局/屋齡等其他鐵律事實塞進亮點區（那些已經在規格區列過了）——2026-09-08 這條規則是使用者在流水帳版、再條列版都不滿意之後才定案的，不要退回舊版本。
- 若來源「訴求重點」是空的，亮點區留空或跟使用者說明沒有素材可用，不要自己編。

填完用 `ctrl+a` + `Delete` 清空整個富文本框再貼新版，不要用 append 造成新舊文案疊在一起。

### Step 5. 照片＆影片、聯絡資料分頁

- 上傳全部照片到「房屋照片」，格局圖/影片非必填可略過。
- 聯絡資料通常已帶入預設名片，不用改，除非使用者另外交代。

### Step 6. 「保存資料，下一步」→ 進第3步「確認刊登方案」

**這步是花錢風險最高的地方，務必照做：**

1. 檢查「購買精選推薦」「超值加購」「購買AI助手」是不是預設打勾（591 常態會預設勾一堆），**全部取消勾選**。
2. 特別注意「同意自動續費」這個子選項，即使精選推薦本身取消了也要確認它沒有殘留勾選。
3. 取消完，看右下角「應付金額」**必須顯示 0 元**才能按「確認刊登方案」。任何非 0 元，都要停下來跟使用者確認要不要付費，不能自己決定付。
4. 送出後如果跳「你還可以買OOO」的加購彈窗（挽留話術、損失曝光數字），一律點右上角 X 或「確定」放棄，不要點「立即支付」。

### Step 7. 完成

給使用者這則廣告連結（`https://sale.591.com.tw/home/house/detail/2/{591物件編號}.html`，物件編號從 URL 或「查看該筆廣告」連結拿），提醒 591 通常要等 3 分鐘才會在搜尋列表顯示，請使用者自己人工檢查一次。

## 規矩（絕對不要違反）

- ❌ 確認刊登方案那步，應付金額不是 0 元絕對不能自己按下去，一定要停下來問
- ❌ 不要把來源頁「本表單係店內部流通資料，不得作為正式銷售文件」那段免責文字之外的內容整段照抄當文案，鐵律事實只能拿來組裝，不能整段貼
- ❌ 文案亮點區不能自己加訴求重點以外的賣點，即使那些是真事實（坪數/格局/學區等）——那些已經在規格區列過
- ❌ 坪數不能四捨五入，一律無條件捨去到小數點後2位
- ❌ 裝潢程度不要看到「空屋」就自動選「尚未裝潢」，固定選「簡易裝潢」
- ❌ 車位/公設子集算不出來就停下來問，不要瞎猜哪個是子集哪個是外加
